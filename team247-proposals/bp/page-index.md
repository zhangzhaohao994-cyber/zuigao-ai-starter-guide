# 正式BP逐页目录（V6）

每项目18页，共54页。私人AI采用最高新增的大众化定位及增长模型。

## 项目01｜大众化私人 AI 智能助理

| 页码 | 标题 | 这一页回答什么 | 对应评审要求 |
| --- | --- | --- | --- |
| 01 | 执行摘要与大众化愿景 | 目标是一个大众化的个人智能机器人；1,000、10,000、100,000人是阶段目标，提醒只是功能之一。 | R4 / R5 |
| 02 | 客户与问题 | 大众化不等于没有首发场景：先用一组高频任务找到持续使用的理由。 | R2 |
| 03 | 产品与使用流程 | 产品应完成“理解需求—处理信息—形成成果—用户确认—后续跟进”的闭环。 | R2 |
| 04 | MVP与交付范围 | 保留大众化目标，以可扩展的任务能力起步；功能和技术边界与团队共定。 | R2 |
| 05 | 市场测算与数据依据 | 把目标放到1,000／10,000／100,000人，同时分别报告激活、付费与持续使用。 | R1 |
| 06 | 竞争与替代方案 | 大众AI市场已有强替代品，低价与奖励需要建立在持续实用性上。 | R1 / R4 |
| 07 | 商业模式与定价 | 1元和10元都先作为价格假设；首笔邀请奖励与后续订阅分开讨论。 | R2 |
| 08 | 单位成本与盈利条件 | 首笔1元全额返给邀请人后，平台需要为这次获客承担实际服务成本。 | R1 / R2 |
| 09 | 首个1,000用户与规模目标 | 首个1,000人要有种子来源，后续再用真实邀请数据推算10倍增长。 | R3 |
| 10 | 一元邀请机制与传播模型 | 一元奖励有机会降低传播门槛，但增长速度取决于每一代实际带来多少新付费者。 | R3 |
| 11 | 价格与规模情景测算 | 用三种价格和三个规模计算资金与贡献，观察增长是否同时改善经营。 | R1 / R5 |
| 12 | 资源预算与现金安排 | 与团队讨论的不只是技术选择，也包括到每个规模时准备多少资金和人力。 | R1 |
| 13 | 90天里程碑 | 目标分阶段升级，技术与增长里程碑由实测门槛连接。 | R3 / R4 |
| 14 | 验证指标与验收 | 增长要同时看真实任务、持续使用与付费，不能只看为了奖励而来的账号数。 | R4 / R5 |
| 15 | 风险与应对 | 用透明规则控制推广与服务风险，不因“一元很少”忽略累计负担。 | R4 |
| 16 | 团队分工与协作 | 我愿意主导产品与市场推进，技术与资源方案希望和团队共同论证。 | R4 |
| 17 | 证据、假设与待验证项 | 公开来源支持背景与约束，项目收入和增长仍来自待验证的假设。 | R1 / R5 |
| 18 | 建议与下一步决策 | 若团队希望探索大众化、可规模化的产品，建议优先讨论私人AI主线与第一阶段投入。 | R4 / R5 |
## 项目02｜医美行业 Agent

| 页码 | 标题 | 这一页回答什么 | 对应评审要求 |
| --- | --- | --- | --- |
| 01 | 执行摘要 | 先为一个明确的行业任务收费，验证审核质量、节省工时与续费。 | R4 / R5 |
| 02 | 客户与问题 | 使用者、审核者和采购负责人分别承担不同角色，必须同时找到。 | R2 |
| 03 | 产品与使用流程 | 交付价值来自资料、版本、审核和成果管理的完整工作流。 | R2 |
| 04 | MVP与交付范围 | 14天试点必须能逐项验收，2,980元对应有限范围。 | R2 |
| 05 | 市场测算与数据依据 | 可服务市场由客户资格和名单验证，不用全部医院数乘客单价。 | R1 |
| 06 | 竞争与替代方案 | 通用工具已经能搭工作流，我们需要证明行业交付更可靠、更省总工时。 | R1 / R4 |
| 07 | 商业模式与定价 | 试点、订阅、公开机构研究与定制必须分别报价，不能混成一个收入模型。 | R2 |
| 08 | 单位成本与盈利条件 | 单试点贡献1,480.80元；如果交付工时翻倍，获客后的利润就可能转负。 | R1 / R2 |
| 09 | 首批客户获取 | 10个付费客户来自可核验的销售漏斗；它是验证批次，不是长期规模上限。 | R3 |
| 10 | 渠道执行与销售流程 | 先诊断一项真实任务，再演示、报价、收款和验收。 | R3 |
| 11 | 三情景财务测算 | 保守、基准和乐观均用同一公式；收入增长不代表已覆盖全部投入。 | R1 / R5 |
| 12 | 资源预算与现金安排 | 内部工程和产品资源有成本，即使现金没有立即支出。 | R1 |
| 13 | 90天里程碑 | 逐批扩大交付，靠真实验收与成熟客户续费决定产品化。 | R3 / R4 |
| 14 | 验证指标与验收 | 把专业性、省时、付费和续费分别测量，只有全部成立才适合复制。 | R4 / R5 |
| 15 | 风险与应对 | 行业知识错误与人工交付失控，是比模型是否能生成更重要的风险。 | R4 |
| 16 | 团队分工与协作 | 我愿意主导产品与市场推进，技术与资源方案希望和团队共同论证。 | R4 |
| 17 | 证据、假设与待验证项 | 公开来源支持背景与约束，项目收入和增长仍来自待验证的假设。 | R1 / R5 |
| 18 | 建议与下一步决策 | 若评审重点是尽快验证付费与交付，行业Agent是更直接的第一轮试点。 | R4 / R5 |
## 项目03｜个人故事视觉小说

| 页码 | 标题 | 这一页回答什么 | 对应评审要求 |
| --- | --- | --- | --- |
| 01 | 执行摘要 | 先让普通人完成一部可玩的私人作品，再验证购买、分享与再次创作。 | R4 / R5 |
| 02 | 客户与问题 | 创作者与玩家是不同角色，只有被故事打动不等于愿意创作或付款。 | R2 |
| 03 | 产品与使用流程 | 把原始经历与虚构分支分开确认，再生成可玩的完整故事。 | R2 |
| 04 | MVP与交付范围 | 免费短篇要完整；付费版的角色、图片、分支和修改次数都应有上限。 | R2 |
| 05 | 市场测算与数据依据 | 首轮市场是能触达且愿完成作品的创作者，不是全部AI用户或所有玩家。 | R1 |
| 06 | 竞争与替代方案 | 竞争优势需要来自完整制作与私人表达，而非单纯扩写更多字。 | R1 / R4 |
| 07 | 商业模式与定价 | 作者为成品付费，玩家免费；首轮按次收费更便于验证低频需求。 | R2 |
| 08 | 单位成本与盈利条件 | 免费作品成本会吞掉付费贡献，分享奖励也需要单独预算。 | R1 / R2 |
| 09 | 首批客户获取 | 先获得100名完成作品的作者，再观察其中谁真的购买。 | R3 |
| 10 | 渠道执行与销售流程 | 先交10部样品，验证作者完成与报价，再扩大渠道。 | R3 |
| 11 | 三情景财务测算 | 保守、基准和乐观均用同一公式；收入增长不代表已覆盖全部投入。 | R1 / R5 |
| 12 | 资源预算与现金安排 | 先确认每部作品能以目标成本交付，再决定建设自动化平台。 | R1 |
| 13 | 90天里程碑 | 把样品交付、受控招募和成熟用户复购分别推进。 | R3 / R4 |
| 14 | 验证指标与验收 | 作品完整、作者认可、玩家玩完和实际购买，需要各自的分母。 | R4 / R5 |
| 15 | 风险与应对 | 故事质量、生成成本和私人素材使用范围决定它能否持续经营。 | R4 |
| 16 | 团队分工与协作 | 我愿意主导产品与市场推进，技术与资源方案希望和团队共同论证。 | R4 |
| 17 | 证据、假设与待验证项 | 公开来源支持背景与约束，项目收入和增长仍来自待验证的假设。 | R1 / R5 |
| 18 | 建议与下一步决策 | 建议用10部完整样品确认作者价值，再决定是创作平台还是按次纪念服务。 | R4 / R5 |
